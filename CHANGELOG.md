# Changelog

## Unreleased

- Fixed the CI `pip check` failure ("pipx 1.18.12 has requirement filelock>=4.2, but you have filelock 3.32.7"). Both CI jobs now install into an isolated virtual environment, so `pip check` and `pip-audit` examine only this project's dependencies and not tools preinstalled on the runner. The project's own set is consistent; `filelock` stays below 4 because the pinned LiteLLM requires it.

- Added employee lookup by name (`find_employee`, authorization-filtered; audit logs only the name length), `get_employee_email`, `get_employee_manager`, `list_direct_reports`, `list_employees`, `get_project_team`, and filters for headcount (role/department/group), exits (role/department), bench duration, new hires, clients (status/industry), and partial project names. Email is returned only by its own tool, with the same access rule as profiles.
- Scope guard now describes allowed topics by category instead of a field list, so email/manager/direct-report questions are no longer refused before authorization. Clarification replies are merged with the pending question for both the planner and the topic guard. Planner dates use the UTC request date.
- A coordinator reply that arrives before any planned delegation (a model does this intermittently on long multi-part questions) no longer ends the turn with "I could not finish all planned steps": the discarded text is replaced by the plan's next step, bounded by the number of steps. Previously only a reply after the first step had run was recovered.
- Reduced false refusals of long multi-part questions: a specialist's scope check now sees the question the coordinator already approved and is told to allow steps that serve it, merged tasks are written as a numbered list instead of a run-on string, and a blocked step now produces its own message ("One part of your request was blocked…") instead of a generic out-of-scope refusal that looked like the whole question was rejected. The exact trigger for the reported year-end attrition question could not be confirmed without the terminal log.
- Fixed the general cause of "the answer ignored part of my question": every agent is now told to apply each stated constraint and to say so when one cannot be applied, the footer lists applied filters, and `list_employees` gained the constraints people naturally add to a list: only people on a project (`assigned`), on a given project or client (`project_name`, `client_name`), and ordering (`order_by`, `descending`) for "longest serving" and "newest joiners". Unknown project or client names return not found instead of an empty list.
- Added an `assigned` filter to `list_employees` so "give 10 data engineers with project names (only those on a project)" returns people who actually have a project. Before, the tool could only filter for people with no project, so the first 10 alphabetical Data Engineers were all shown with "None".
- Planner replies are now parsed leniently around the JSON (stray text or a fence is ignored) but validated strictly, a malformed plan gets one repair attempt, and every planning failure is logged with a value-free reason so it can be diagnosed from the terminal. This was added after a planning failure ("I could not create a valid company-data plan") that followed the longer planner prompt; the exact cause could not be confirmed without the terminal log.
- The planner now sees a capability table generated from the specialists' real tools plus validated example plans, because a prose rule alone did not stop it from splitting "10 data engineers with their project names" into a workforce step and a client/project step that cannot do the job. The skill also tells the specialist to pass the number the user asks for as `limit`.
- Added `include_projects` to `list_employees` so "give all data engineers with their project names" is one call. Before, no tool joined people to projects, so the specialist declined or the coordinator tried one profile lookup per person. The planner is also told never to plan one step per person in a list.
- Delegation is now deterministic: the specialist receives the planner's validated task, not the coordinator model's rewording (a bare "Juniper" had been read as an industry filter and the correct answer was then refused). Added `get_client_details` for "tell me about <client>", and status filters are now validated per tool, so `list_clients` accepts active/inactive and "all" means no filter instead of failing with a project-status error. The planner is given the company's client names and plans a lookup for a bare client, project, or person name.
- Fixed in-scope questions being refused when they named a client that matches a real-world company ("what projects does Acme have", "tell me about Juniper"). The scope guard now receives the company's actual client names as ground truth and has worked in-scope and out-of-scope examples, including vague questions that only need a detail clarified. Questions about an outside organization's own business, hiring, or finances are still refused.
- "My", "me", and "I" now resolve to the verified signed-in employee, so "What is my email address?" is answered directly instead of asking for an ID. A monthly provider cap is now detected, not retried, and reported accurately instead of as a one-minute rate limit.
- Planner now merges independent steps for the same specialist into one delegation before execution, roughly halving model calls for multi-part questions, and the coordinator and specialist time limits are raised to 300 and 120 seconds so a paced multi-step question no longer ends in a node timeout.
- Redesigned the answer format to be answer-first: a plain bolded answer sentence, an optional table, a quoted Note, an In short line only for multi-topic answers, and a one-line As-of footer that never shows N/A. Added fixed date, number, status, and table-column conventions plus worked examples in the coordinator skill, and the same style rules in every agent's shared instructions. List tools now return 20 rows by default (up to 100 on request) and the footer never names the signed-in user's role. The employee skill now continues from a name search to the profile instead of asking what to look up.
- Added a shared resilient model layer (`ResilientLiteLlm`): transient provider errors, including Cohere Trial-key rate limits, are retried with backoff in one place for every model call, with an optional `MODEL_CALLS_PER_MINUTE` pacer. Guard and planner no longer have their own retry loops, and a rate limit is reported as such instead of as a failed safety check.
- Relative dates (today, yesterday, last week, ...) are now computed in Python and given to the planner as a table instead of being calculated by the model. `list_employees` now lists current employees by default, role names such as "QA Engineer" map to stored roles, and list results state their total up front.
- A date window now requires both bounds. A rejected duplicate delegation can no longer advance the plan, and an early model answer after a returned step triggers the next planned delegation.
- Replaced placeholder employee names ("Demo Employee 13") with unique realistic fictional names and matching `example.invalid` emails. Clients and projects keep their names.
- Added coordinator answer-format guidance: direct Result, optional Details/Notes, supported date/filter metadata, explicit partial-list limitations, and a final factual Summary. No extra model calls; live formatting adherence remains unverified.
- Added mandatory structured planning before specialist delegation, session-visible plan/progress, fixed clarification responses, and sequential plan enforcement. Live plan quality remains unverified.
- Added four native ADK runtime skills with domain workflows, tool guidance, permissions, and refusal examples.
- Added input/output scope guardrails, specialist-specific checks, fail-closed reviewer behavior, unreviewed streaming suppression, and known-key echo protection. Live classifier reliability remains unverified.
- Added a Google ADK coordinator and three AgentTool specialists using Cohere via LiteLLM.
- Added 11 fixed read-only tools for workforce, clients/projects, and authorized employee profiles/history.
- Added deterministic synthetic seed data, read-only runtime connections, default-deny permissions, separate audit logging, and session-local employee references.
- Added offline unit/integration tests, a gated live smoke test, evaluation checklist, and Windows/Linux CI.
- Live Cohere acceptance remains unverified until credentials are configured.
- Release is blocked by the audited filelock vulnerability/constraint conflict documented in the README.
